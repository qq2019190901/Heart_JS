## 修复的真实运行时 Bug（3 个，都是会崩/失效级别）
1. **LAN 模式 AI 回合必然 ReferenceError**（`src/App.tsx`）
   `latestDecision` 在 setTimeout 回调外被引用，而它只在回调内声明。改为
   `const decision = getAiPlayDecision(gameState)` 先求值，并补上 `if (!lanIsHostRef.current) return;`
   （只有房主驱动 AI）。**这条会让局域网对战完全不可玩。**
2. **Electron 端口回退永不生效**（`electron/main.ts`）
   `EADDRINUSE` 时原代码 `resolve()` 而非 `reject()`，导致
   `tryListen(9000).catch(() => tryListen(9001))` 的 9001 回退永远不执行。
   重写为 `tryListen(port): Promise<number>` + `for` 循环遍历 `PREFERRED_PORTS = [9000, 9001]`，
   并正确清理 `once` 监听器避免陈旧 handler。
3. **所有屏幕卡片恒定 1.3 倍缩放**（`src/hooks/useResponsive.ts`）
   `getCssViewportSize()` 只返回 `{vw, vh}`，而 `computeResponsiveScale` 需要 `minDim`/`maxDim`。
   `minDim === undefined` 使所有 `if (minDim < 400)` 为 false，**360px 手机上 `.cardScale` 也落到
   else 分支恒为 1.3**。已改为返回完整四字段对象。

## 关键技术约定 / 踩坑（重要）
- **shell 在本机持续损坏**：`ls`/`dirname`/`head`/`tail` 全部 `command not found`（exit 127），
  `cd` 报 `cd: null directory`。**解决办法：用 Node 直调工具链**
  —— `node node_modules/typescript/bin/tsc`、`node node_modules/vitest/vitest.mjs`、
  `node node_modules/eslint/bin/eslint.js`，输出重定向到文件后用 Read 读。
  已固化为 `scripts/run-checks.mjs`，`npm run check` / `npm run lint` 均可直接用。
- **ESLint 必须排除构建产物**：`android/app/build/**`、`_staging`、`release`、`dist-electron`
  会产生伪错误（`Definition for rule '@typescript-eslint/no-unused-vars' was not found`）。
  `eslint.config.js` 的 `globalIgnores` 已补全。
- **类型改造的两个反直觉点**：
  - 发送函数的参数要用 `object` 而不是 `Record<string, unknown>` —— `GameState` 无索引签名，
    `Record` 不兼容。
  - 事件 payload 要用 `Record<string, unknown>` 的宽类型；用窄联合会让所有 emit 处推断成 `never`。
- **PeerJS 构造是重载函数**：`new Peer(undefined, opts)` / `new Peer(peerId, opts)` 都不合法，
  必须写成 `desiredId ? new Peer(desiredId, opts) : new Peer(opts)`。
- **AI 回合 effect 的竞态**：两个 AI effect（single / lan）共用 `aiTimeoutRef`，存在互相覆盖的隐患。
  已引入 `aiTurnGenRef` 世代计数器：计时器捕获调度时的世代号，执行时不等则直接 return；
  手动出牌（`handleCardClick`）也会递增世代号并清掉待执行计时器。
- **`showPassUI` 是纯死状态**：只写不读，UI 实际由 `gameState.phase` 驱动。已整块移除。
- **`exhaustive-deps` 的 2 个警告是刻意保留的**：AI effect 只从 `gameState` 派生决策，
  依赖 `currentPlayerId` / `phase` / `trickJustCompleted` 三个原语是对的；若把整个 `gameState`
  放进依赖数组，每次状态对象变化都会重启计时器，反而引入 bug。已在代码内写注释 + 定向 disable。
