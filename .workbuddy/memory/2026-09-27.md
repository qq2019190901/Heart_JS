## 关键经验（下次直接复用）

### 1. git 的多个 -m 不会生成多个提交
```
git commit -m "A" -m "B"     # 错！合成一个提交，A 和 B 变成两个段落
```
必须**每个提交一条独立命令**，用 `&&` 串联：
```
git add X && git commit -m "msg1" && git add Y && git commit -m "msg2"
```
我第一版踩了这个坑，把 4 个改动合成了 1 个错误提交，靠
`git reset --soft HEAD~1` + `git restore --staged .` 回滚（工作区完好无损）。

### 2. 单个文件按语义拆多个提交：拆分 hunk + git apply --cached
App.tsx 一个文件里混了「AI 回合修复 / 类型安全 / 移除死状态」三件事，做法：
- `git diff -- src/App.tsx > app-full.patch`
- Node 脚本按 `@@` 切成 hunk，**按 hunk 索引显式分组**（内容关键字自动分类不可靠，
  试过 AI_MARKERS 正则，边界 hunk 会漏）
- 每组拼回 `diff 头 + 该组 hunks`，写成独立 patch
- 依次 `git apply --cached --recount`，每步先 `--check` 预检
最终 A=19 / B=9 / C=4 hunk，全部干净应用。App.tsx 最终 `git diff` 为空，
确认无遗漏。

### 3. Node 里 spawnSync('git') 在这台机器上会 EBUSY
改用 bash 先把 diff 写文件，Node 再读。路径要用 Windows 形式
（`/tmp` 对 Windows node.exe 不成立）。

### 4. 提交顺序要满足编译依赖
- protocol.ts 必须在 App.tsx 类型清理之前（后者 import 它）
- deck.ts 必须在 game/* 之前
- Card.tsx 删 animate prop 必须在 App.tsx 删 animate={false} 传参**之后**
  （反过来会出现 JSX 传了不存在的 prop → tsc 报错）
- Table.tsx / LanLobby.tsx 的 props 删除同理
